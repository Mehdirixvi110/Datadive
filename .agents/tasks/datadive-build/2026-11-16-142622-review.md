# Datadive marketing site — full-state contract review (pass 2)

The Datadive build is a Next.js 15 App Router marketing site whose entire public surface is driven by Airtable through a single server-only data-access layer, with seed fallback so the site builds and renders with zero environment variables. This pass re-reviews the whole `datadive-web` state against the locked design, independently re-runs the zero-env gate, and checks whether the one MEDIUM finding from the previous pass (slug auto-generation and uniqueness not wired) has been fixed. The zero-env gate passes end to end (build, lint, 100/100 Vitest) and every contract listed in the review scope is implemented faithfully. The prior MEDIUM is now resolved: both the project and blog create/update actions derive a slug from the title when blank and make it unique against the other records before writing.

Watch for: nothing blocking. The previously-flagged slug gap is fixed (confirmed), and no new HIGH or MEDIUM issue was found.

**Verdict**: APPROVED

## High-level view

The Airtable boundary holds. Only `src/lib/airtable/*` touches the network; `client.ts`, `read.ts`, and `write.ts` all open with `import 'server-only'`, and the ESLint `no-restricted-imports` rule blocks `airtable` and `**/lib/airtable/client` everywhere except inside that directory. Caching is split by audience exactly as designed: public reads pass `next:{revalidate:3600,tags}`, admin reads and all writes pass `cache:'no-store'` with no tags, so the admin UI always sees live Airtable state.

The no-credential story is coherent. Every read gates on `hasAirtableCreds()` and returns typed seed data when creds are absent; with creds present, singletons fall back to the seed singleton on an empty table, lists return the real empty set, and `getReviews()` is the one deliberate exception that reinjects seed placeholders on an empty published set. The `hasDetail` predicate (published and non-empty body) is the single rule feeding `getProjectDetailSlugs()`, `getProject()` (null unless published), the sitemap, and the `/work/[slug]` static params.

Auth fails safe. `hasAuthCreds()` is checked before any `auth()` call in the three entry points (middleware, the two guards, the NextAuth route), so a zero-env build never trips Auth.js's lazy `MissingSecret`; the build confirms no construction throw. Two guards share one allowlist check: `requireAdminPage()` redirects, `requireAdmin()` throws `AuthError`, and `withAdmin()` keeps a narrow catch that re-throws `NEXT_REDIRECT`/`NEXT_NOT_FOUND` control flow so success navigation survives.

Image handling is locked to the Blob host. `next.config.ts` restricts `remotePatterns` to `*.public.blob.vercel-storage.com` with `dangerouslyAllowSVG:false`, image-URL fields are Zod-validated to a same-origin path or that host only, and seed placeholders are committed raster PNGs — so `next/image` never hits the SVG-optimizer 400 and the zero-env render shows no broken art. The WhatsApp link, footer, and nav are all read from Settings; a grep of the components found no hardcoded number, email, or domain. Stored Markdown renders through `rehype-sanitize`. Git is isolated: the repo root resolves to `datadive-web` and nothing outside it is tracked.

### Prior MEDIUM (slug auto-generation + uniqueness) — resolved

The previous pass flagged that `slugify`/`uniqueSlug` existed and were unit-tested but never called by any admin action, so a blank slug was a validation error and two projects/posts could collide on one slug. Both paths are now wired. `projectSchema.slug` and `blogPostSchema.slug` use `optionalSlugSchema.optional().default("")`, so a blank slug passes validation instead of being rejected. `createProjectAction`/`updateProjectAction` and the blog equivalents pass a `prepare` hook that runs inside `withAdmin()` after validation:

```ts
async function resolveProjectSlug(input, excludeId?) {
  const existing = (await getAllProjects())
    .filter((p) => p.id !== excludeId)
    .map((p) => p.slug);
  return { ...input, slug: uniqueSlug(input.slug || slugify(input.name), existing) };
}
```

Excluding the edited record's id means re-saving a record keeps its own slug rather than bumping to `-2`. `adminMutate` resolves the cache tags from the same transformed input, so `project:{slug}`/`blogpost:{slug}` revalidation uses the persisted slug. This closes the contract gap at both create and update for both entities.

### Airtable boundary and audience-split caching

`cacheInit` in `client.ts` is the whole caching contract in one function: public audience returns `{ next: { revalidate: 3600, tags } }`, admin returns `{ cache: 'no-store' }`. Writes hard-code `cache:'no-store'`. This is the fix the design calls out for Next 15, where an explicit `next:{revalidate,tags}` would otherwise still populate the Data Cache even under `force-dynamic` — admin reads deliberately carry no tags and no-store so out-of-band Airtable edits show immediately. The token-bucket limiter (capacity 5, ~4/s refill, concurrency cap 4) and 3× backoff on 429/5xx wrap every call; the in-process per-instance limitation is the documented, accepted v1 trade-off.

### No-creds fallback and the reviews exception

`readSingleton` returns the seed singleton on an empty table; `readList` returns the mapped/filtered/sorted real set (seed only when creds are absent). `getReviews()` is the sole list that returns `SEED_REVIEWS` when the published set is empty, matching FR-9.2, while `getBlogPosts()` keeps the empty-set behavior so `/blog` can show its empty state. Reads never throw into a page: each catch logs and degrades to seed or last-good.

### Auth posture

`resolveAdminSession()` short-circuits to `null` on `!hasAuthCreds()` before calling `auth()`, re-checks the allowlist every call (immediate revocation), and lowercases the email. The middleware matcher is scoped to `/admin/:path*`, excludes `/admin/login`, and checks creds before delegating to the Auth.js wrapper, keeping the public site auth-free. The Blob upload route runs `requireAdmin()` in `onBeforeGenerateToken`, maps `AuthError` to 401, restricts content types to jpeg/png/webp/avif, caps at 8MB, and disallows SVG.

### Verified gate (zero env, from `datadive-web`)

`npm run build` succeeds (18 public routes prerendered; all `/admin/*` dynamic; `/work/[slug]` static params emit only hasDetail slugs). `npm run lint` reports no warnings or errors (the `next lint` deprecation notice for Next 16 is informational and does not fail the step). `npx vitest run` passes 100/100 across 9 files including the admin-action, contact, auth-allowlist, and DAL integration suites. Git `rev-parse --show-toplevel` resolves to the `datadive-web` path and `git ls-files` lists nothing outside it.
